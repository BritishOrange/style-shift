# Model Card: StyleShift / Qwen2.5-1.5B-Instruct

Карточка модели составлена по формату **Model Cards for Model Reporting**
(Mitchell et al., Google, 2019) и описывает модель **в контексте проекта StyleShift** —
локального сервиса смены стиля текста.

| Поле | Значение |
|------|----------|
| Версия карточки | 1.0 |
| Дата | 2026-10-28 |
| Проект | StyleShift (`BritishOrange/style-shift`) |
| Базовая модель | [`Qwen/Qwen2.5-1.5B-Instruct`](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct) |

---

## 1. Model Details

### Person / organization developing model

- **Базовая модель:** Qwen Team, Alibaba Cloud.
- **Применение / обёртка в продукте:** проект StyleShift (локальный Flask-сервис,
  пакет `styleshift`): промпт-инжиниринг, few-shot пример, post-processing ответа,
  HTTP API и UI. Дообучение (fine-tune) не выполнялось.

### Model date

- Релиз линейки Qwen2.5: сентябрь 2024.
- Интеграция в StyleShift: октябрь 2026.

### Model version

- Hugging Face id: `Qwen/Qwen2.5-1.5B-Instruct`
- Конфигурируется через `STYLESHIFT_MODEL_ID` (по умолчанию указанный выше).

### Model type

- **Тип:** Causal Language Model (авторегрессионная LLM), instruction-tuned.
- **Архитектура:** Transformer (RoPE, SwiGLU, RMSNorm, QKV bias, tied embeddings).
- **Параметры:** ~1.54B (non-embedding ≈ 1.31B); 28 слоёв; GQA 12 Q / 2 KV.
- **Контекст:** до 32 768 токенов (в StyleShift вход ограничен 2000 символами).
- **Инференс в проекте:** CPU, `torch.float32`, `device_map="cpu"`,
  sampling (`temperature=0.3`, `top_p=0.8`, `repetition_penalty=1.12`).

### Training algorithms, parameters, approaches

- Pretraining + post-training (SFT / alignment) выполнены командой Qwen;
  детали — в [Qwen2 Technical Report](https://arxiv.org/abs/2407.10671) и
  [блоге Qwen2.5](https://qwenlm.github.io/blog/qwen2.5/).
- В StyleShift используется **zero-/few-shot prompting** без изменения весов:
  system prompt (сохранение смысла, смена только стиля) + один few-shot пример
  «неформальный → деловой» + пользовательский запрос со стилем из набора
  `academic | business | informal | poetic | simple | news`.

## 2. Intended Use

### Primary intended uses

1. **Перефразирование** коротких русскоязычных (и смешанных) текстов с сохранением
   смысла и сменой регистра/стиля речи.
2. Демонстрация / учебный локальный NLP-сервис без отправки текста во внешнее API.
3. Поддерживаемые целевые стили в UI: академический, деловой, неформальный,
   поэтический, простой, новостной.

### Primary intended users

- Разработчики и студенты, изучающие NLP / MLOps.
- Конечные пользователи на **localhost** (личный ПК), не публичный SaaS.

### Out-of-scope use cases

- Юридически значимые, медицинские, финансовые или иные high-stakes решения.
- Генерация вредоносного, дискриминационного или вводящего в заблуждение контента.
- Машинный перевод «как продукт» (задача — стиль, не перевод между языками).
- Обработка персональных данных третьих лиц без правового основания.
- Высоконагруженный production без отдельного capacity/security review
  (текущий деплой — single-process Flask на `127.0.0.1`).
- Использование выхода модели как единственного источника фактов
  (модель может галлюцинировать).

## 3. Factors

### Relevant factors

| Фактор | Почему важен |
|--------|----------------|
| **Язык входа** | Модель мультиязычная (≥29 языков), UI и промпты StyleShift ориентированы на русский. |
| **Длина текста** | Лимит API: 2000 символов; очень короткие/очень длинные входы ведут себя иначе. |
| **Целевой стиль** | Качество и «узнаваемость» стиля различаются (например, poetic vs news). |
| **Домен текста** | Сленг, узкая терминология, опечатки влияют на устойчивость перефраза. |
| **Аппаратное окружение** | CPU-only, float32 → латентность и детерминизм отличаются от GPU/bf16. |
| **Случайность sampling** | `do_sample=True` → повторные запросы дают вариации. |

### Evaluation factors (рекомендуемые срезы)

- Язык: RU / EN / code-mixed.
- Стиль: каждый из 6 id.
- Длина: короткий (&lt;50 символов), средний, близкий к лимиту.
- Домен: бытовой диалог, деловая переписка, учебный текст.

*В текущей версии репозитория формальный бенчмарк по срезам не зафиксирован;
ниже — предлагаемые метрики и ожидаемое качественное поведение.*

## 4. Metrics

### Model performance measures (для задачи StyleShift)

| Метрика | Описание | Цель |
|---------|----------|------|
| **Meaning preservation** | Сохранение фактов/интента (экспертная 1–5 или NLI/embedding similarity) | Высокая |
| **Style adherence** | Соответствие выбранному стилю (эксперт / классификатор стиля) | Высокая |
| **Hallucination rate** | Доля ответов с новыми фактами | Низкая |
| **Empty / refuse rate** | Пустой ответ после `clean_reply` → HTTP 500 | Низкая |
| **Latency (p50/p95)** | Время `POST /api/rewrite` на CPU | Мониторинг |
| **Availability** | Доля времени `health.status == ready` | Высокая после прогрева |

### Decision thresholds

- Вход пустой / не строка → **400**.
- Неизвестный `style` → **400**.
- `len(text) > 2000` → **400**.
- `model_status != ready` → **503**.
- Пустой ответ модели после очистки → **500**.
- Успех → **200** + JSON `{original, style, styleLabel, rewritten}`.

### Variation approaches

- Стохастический декодинг: при необходимости стабильности снизить `temperature`
  или перейти на greedy (`do_sample=False`) — изменение конфигурации инференса.

## 5. Evaluation Data

### Datasets

- Отдельный публичный eval-набор **в репозитории StyleShift не поставляется**.
- Для отчётности рекомендуется собрать небольшой gold-set (десятки пар
  «текст → стиль → эталонный перефраз») вручную.

### Motivation

- Задача узкая (style transfer / paraphrase), стандартные LLM-лидерборды
  (MMLU и т.п.) слабо отражают продуктовое качество StyleShift.

### Preprocessing

- Trim пробелов; удаление типовых преамбул модели (`clean_reply`);
  chat template токенизатора Qwen.

## 6. Training Data

Базовая модель обучена Qwen на крупных текстовых корпусах (pretrain) и данных
instruction-tuning / alignment (post-train). Полный состав корпусов
**не раскрыт публично в деталях**, достаточных для полного аудита;
ориентир — документация и technical report Qwen.

StyleShift **не добавляет** собственных обучающих данных и **не дообучает** веса.
Единственный «обучение-подобный» сигнал в рантайме — фиксированный few-shot
пример в промпте.

## 8. Ethical Considerations

- **Конфиденциальность:** инференс локальный; модель и кэш Hugging Face хранятся
  на машине пользователя. Текст запроса не уходит на сторонний inference API
  StyleShift, но **первый** download весов идёт с Hugging Face.
- **Смещение стиля/языка:** выход может отражатьbiases предобучения (стереотипы,
  неравномерное качество по языкам/доменам).
- **Злоупотребления:** перефразирование может использоваться для маскировки
  токсичного или мошеннического текста — продукт не предназначен для этого.
- **Достоверность:** несмотря на инструкцию «не добавлять фактов», LLM может
  искажать смысл; человек должен проверять критичные тексты.
- **Доступность:** CPU-инференс может быть медленным; это влияет на UX, но не
  на корректность политики доступа (сервис только localhost).

---

## 9. Caveats and Recommendations

1. Не использовать выход без проверки там, где важна фактическая точность.
2. Не выставлять сервис в публичную сеть без auth, rate limit и threat model.
3. Для воспроизводимости фиксануть версии в `poetry.lock` и при возможности
   хеш/ревизию весов модели.
4. Для production-качества — собрать eval-set, заполнить §7 числами, рассмотреть
   более крупную модель или GPU, калибровку декодирования.
5. При смене `STYLESHIFT_MODEL_ID` обновить эту Model Card (версия, метрики, риски).
6. Помнить лимит 2000 символов и few-shot bias в сторону «делового» стиля в примере.
